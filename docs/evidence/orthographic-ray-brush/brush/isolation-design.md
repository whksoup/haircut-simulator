## Characterization

Command: bundled Node 24.19.0 executable, `--test tests/ray-brush-isolation-feasibility.test.mjs`. Both tests pass by characterizing a limitation, not by meeting ORB-2. Production guide store, binder and length audit are used. Reconstruction is a CPU specialization of the production shader for equal unit lengths, identity strand frames, clump 1 and zero jitter/length variation. At each control point with unchanged guide lengths and strand frames, reconstruction is `P_s = root_s + L_s R_s sum_g(w_sg p_g)`. For a single editable guide and any protected strand with positive weight on that guide, `delta P_s = L_s R_s w_sg delta p_g`. Since the frame is invertible and the scalar positive, exact exclusion requires `delta p_g = 0`. The tolerance only permits tiny edits: the fixture's excluded/eligible response ratio is approximately 0.096855. Useful movement of 0.005 therefore produces about 0.000484 of excluded motion, far above the 0.000002 example tolerance. Null-space constraints with multiple editable guides can occasionally allow changes, but cannot solve the mandatory single-guide selected facet case. A head-visibility oracle cannot add missing shape degrees of freedom.

Changing length/tangent to compensate is not a general escape: it affects the entire shared row, protection is required at every reconstructed vertex, and multiple protected strands with different blend weights overconstrain those parameters. Brush shape edits should retain the existing length/tangent contract regardless.

## Options and recommendation

1. **Reject every guide edit that would touch any excluded reconstructed point.** Preserves the current representation and history, but fails useful single-facet brushing in the fixture. Not acceptable under B1/B3.
2. **Facet-local guides or facet-local binding.** Removes cross-facet leakage, but changes the existing smooth hairstyle at facet boundaries unless old blends are materialized first. It still cannot separate visible and hidden strands within one facet. Not sufficient for B2.
3. **Persisted sparse strand brush curves/corrections — recommended necessary direction.** Give each contacted rendered strand independent authored shape degrees of freedom. Retain all current guides and their behavior as the base field; brush updates an explicit persistent per-strand layer. Reconstruct the complete strand before visibility/contact/length constraints and upload only changed layer rows. This can represent exact protected domains without compensation edits to excluded guides/strands and without per-move rebinding. It is a representation expansion, not an implementation detail of CombTool.
4. **Promote every strand to a normal guide.** Can represent the geometry, but changes guide membership/binding, exceeds the current 8192-row cap against 200000 possible strands, forces broad history/schema/tool work, and destroys the current guide-scale performance assumption. Larger and less isolated than option 3.

Option 3 is a design candidate, not an approved or demonstrated performance solution. B2/B3 remain unchanged; I1 and the workstream's guide-only history/row language need an explicit scope revision before implementation.

## Proposed option 3 contract for review

- Add a `StrandEditStore` under `groom/`, with identity-preserving `copyFrom`, validation, bounded finite point arrays, and deterministic serialization. Groom schema increments from 6; old files migrate to an empty layer, with unchanged guide schema and guide/seam identities. Camera and mask settings stay transient.
- Store normalized local corrections after the base guide blend, with root correction exactly zero, keyed to the actual deterministic sampled root. Avoid using the float random seed as a unique ID. Current facet-wide ordinal is not stable across triangle density changes: earlier triangle counts change the hash index of later triangles. A record must include master seed, facet, ordinal and a root-position/normal fingerprint, and apply only on an exact matching sample. Keep unmatched records dormant through density changes so returning to the same sampling revives them; facet removal removes its records in the existing structural snapshot. Replaced topology/seed needs an explicit invalidation/remap policy. A sampler redesign is outside this minimal option.
- CPU reconstruction and GLSL must use the same ordering: base blend, procedural variation/jitter, strand edit, growth clipping, presentation. To avoid accidental styling changes on later look/guide edits, choose and document the coordinate/scaling semantics. Recommended first prototype: normalized frame-space offsets following current strand frame and length, applied after jitter. Base finite-comb edits then continue to affect brushed strands, but length and cutting behavior require the next bullet; an overlay cannot simply be bolted on and called complete.
- Cutting must truncate/resample the final curve and update corresponding corrections, not merely shorten the base guide while retaining an unrelated correction parameterization. Finite comb can continue editing the base guides, but a post-change reconstraint pass for affected edited strands may be needed to preserve agreed strand lengths. These edits must be included in the same undo transaction. This cross-tool requirement needs a prototype before approving the representation as final.
- Introduce a sparse strand-layer history patch (before/after records, including absent records); guide transactions that also change the layer must capture both. Structural snapshots include the layer. Restore updates touched texture rows and preserves store references. Existing guide strokes without layer edits keep their current cheap path. This is an explicit revision of `history.js`'s two-patch policy.
- Renderer keeps root allocations and 3-guide bindings. Add one correction-row attribute and a separately tiled data texture, avoiding a row-per-strand texture height beyond GPU limits. Slot assignment is derived; authored record identity never depends on GPU row or allocation offset. Upload touched rows; mark bounds/index invalidation after base-guide, seam/binding, look, topology or sampling changes. Maximum dense correction storage alone is about 28.8 MB for 200000 strands × 9 RGBA float texels, before history/CPU caches; sparse editing avoids paying all of this initially.
- Hair-domain solver receives reconstructed curves, explicit eligible contacts and protected vertices/segments. Root and hidden points stay pinned through every solve and final relaxation. Protect both endpoints of any segment with an occluded portion, or split geometry under a separately agreed representation. A fully taut interval between two protected endpoints admits no length-preserving bend: reject that interval, while allowing a free visible suffix. Visibility is head-only and evaluated at each strand's screen rays, not its guide/root or the cursor-center ray.
- `headVisibility.js` owns transformed surface queries. A CPU broad phase for reconstructed strand contacts and a measured head-query strategy are necessary: direct queries across up to 1.8 million vertices cannot be assumed to meet I3. Do not promise performance based on guide-count reasoning once solving strands.

## Review follow-up: absolute sparse curves

The independent reviewer confirmed the blend blocker and highlighted that existing blended strand edges are not equal-length guide edges. An exact promotion must retain each actual edge rest length; resampling to the guide's nine equal arc steps could itself move protected hair. Additive corrections make later base changes convenient, but exact brush-geometry cutting still requires direct strand contacts, a final-curve prefix cut and rebase. A simpler alternative for the prototype is **absolute final-curve overrides**:

- Promotion stores the existing nine reconstructed mesh-local vertices relative to the sampled root, with pinned root zero, total arc length and eight individual rest lengths. The brush solver preserves these lengths and protected vertices. No initial resampling or guide mutation occurs.
- Rendering uses the promoted curve in place of guide reconstruction, followed by growth clipping and presentation. The current rendered jitter/length variation is captured at promotion, so the visible shape does not jump. Strand edits are authored, not a shader-only transient clamp.
- Finite comb and scissors directly process promoted curves alongside guide curves. Extract a narrow domain contact/frame adapter instead of wrapping an invisible tool. The length solver accepts scalar rest length for unchanged guides and per-edge rest lengths for promoted curves. Scissors tests the real final curve, cuts at cumulative arc distance and writes the remaining prefix; extending/refining its cut adapter is preferable to applying guide cut fractions to unrelated curves. Both domains commit atomically in one history entry.
- This deliberately removes promoted curves from indirect base guide shape changes. Direct finite comb/cut strokes still edit them. Seam/binding changes and guide add/remove affect unpromoted hair only; promoted hair keeps its authored geometry. Facet removal removes its promoted records. Look clump/jitter/length-variation changes affect unpromoted hair only unless a separately designed transform is adopted. Global length controls must explicitly scale promoted curves with their matching facet, preserving their shape and updating rest lengths; root sampling density uses the fingerprint/dormancy policy above. These are visible product semantics and require coordinator approval, not silent defaults.
- A complete topology/seed invalidation contract remains necessary: new namespace must never apply old curves at different roots. Keeping records dormant by a topology+sampler+seed namespace avoids incorrect reuse and permits exact return; application limits and pruning should prevent unbounded orphaned records.

Absolute curves make comb/cut and protection more tractable than delta rebasing, but the seam/look semantics are a tradeoff. Neither option is yet approved. The next test-only prototype should compare both on a brushed-strand blade hit that misses all guide curves and on a finite-comb stroke, with exact undo/redo and reload. Required new scope is explicit in either design.
